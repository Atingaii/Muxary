## 2. 必要术语与不变量

以下仅约束本扩展，沿用仓库已有 Agent、Job、Receipt 与原生会话定义。

- **项目（Project）**：CCB 的项目身份及项目根目录，不因 managed worktree 另造项目身份。
- **Agent 工作目录（workspace）**：CCB 声明/启动绑定给一个 Agent 的工作目录；可以是主目录、已有 worktree 或原架构支持的其他模式。不是每个 Job 可任意选择的 cwd。
- **Git worktree**：同一 Git 仓库的一个检出工作目录；不是 Agent、Job 或原生会话的别名。
- **画布卡片**：一个现有 Agent 的摘要视图。移动/隐藏卡片不会移动/关闭原生 pane、终止 Agent 或改变工作目录。
- **当前选择**：唯一的项目与 Agent 选择；专注、画布、导航、composer 和 diff 使用同一身份，不各自维护派活目标。

必须保持：

1. 派活仍进入原 ccbd；receipt/HTTP 202 不表示完成，unknown 不自动重发。
2. 工作目录信息不是文件访问沙箱、永久进程 cwd、只读强制或单写锁。CLI 或工具可能合法切换自身 cwd；界面不承诺持续监控每次实际文件访问。
3. 共享目录明示无写入隔离；不把“用户确认过”当作互斥保证。
4. 选择 Agent 不启动任务，拖动/关闭展示卡不改变原生运行态。
5. 工作台任务与原生会话保留来源边界；不为视觉统一按文本去重或合并成伪权威历史。

## 3. 两种视图与交互

### 专注

- 默认进入专注；左侧按项目 → 工作目录 → Agent 导航。目录来自实际 Agent 绑定，是分组与只读属性，不新增“选目录后 Agent 自动迁移”的暗示。
- 保持唯一 composer，目标 Agent 持续可见；切换/回到专注不自动发送，中文 composition 不被全局快捷键截断。
- 右侧信息默认收起；窄屏导航与上下文抽屉互斥，scrim、Esc、焦点恢复可验证，不同时覆盖主内容。
- 当前“开始新任务”若仅聚焦输入，应更名/解释为实际行为，不假称创建 Agent、会话或 worktree。
- Command 面板导航已挂载项目、当前项目 Agent 与页面操作；“打开本机项目目录”仅打开明确确认的对话框，不直接派活或启动。

### 画布

- 用成熟引擎提供平移、缩放、拖动与定位；自动排列确定、筛选可恢复，不因状态刷新持续跳位。
- 卡片仅有轻量身份、真实状态与目录摘要，不内嵌 Markdown 会话、composer、xterm 或逐节点订阅。
- 不画不存在的编排连线；卡片数是 UI Agent 数，不是同时运行的 CLI、流或连接数。
- 选中卡片与左栏/专注共享身份；提供可发现的“返回专注”与定位当前 Agent，不只依赖鼠标拖拽。
- 布局只影响本机浏览器呈现，不引入服务端画布存储或第二个执行模型。当前摘要画布最多 100 个 Agent，更多 Agent 仍可从导航访问；布局最多保存 20 个项目，原始序列化读取预算是 256×1024 个 UTF-16 code units，不冒称 UTF-8 字节预算。
- 普通视口与 fit-all 分别测试；fit-all 使全部卡可见，不能拿普通视口裁剪收益冒充 fit-all 性能。

## 4. 工作目录身份与 diff scope

CCB 已有 [`WorkspacePlanner`](../../lib/workspace/planner.py)、[`WorkspaceMaterializer`](../../lib/workspace/materializer.py)、[`WorkspaceBindingStore`](../../lib/workspace/binding.py)、[`WorkspaceValidator`](../../lib/workspace/validator.py)。工作台只消费现有 Agent 声明/绑定，不新增目录管理器；配置/创建入口进入原 CCB 配置页及其激活流程。

客户端只提交项目/Agent 身份，不能提交任意文件系统路径作为 diff 根。服务端依据实际可信 Agent 绑定、canonical path 和允许归属解析范围；不能仅因某路径出现在客户端状态或未验证 snapshot 中就授予读取范围。managed worktree 应验证回映同一项目，普通目录模式按原有合法范围处理，不错误地把所有 workspace 限为项目根的子目录。

- 响应/界面标明实际目录与 scope；仅展示 tracked、unstaged diff 时明确说明，不冒充完整 Git 状态或所有产物。
- scope 缺失、过期、身份错配、路径替换或 symlink 越界等校验失败：**明确报错，不静默 fallback 到 project_root**。
- 多 Agent 共享目录：标为“目录差异，非该 Agent 独占产出”。切 Agent 不能把旧目录 diff 当新目录结果展示。
- 原生工作目录/配置错误应保留有用诊断，不把 Validator 拒绝改成成功。
- 声明/绑定目录与实际启动路径的身份可测试，但 `/proc` 某次 cwd 相等不是永久写入隔离的 oracle。

原 Materializer 内部已有 stale registration prune 与特定重试分支 force 行为。本轮不修改也不借 UI 对其新增背书；“无新增 Web force/prune 入口”不等于声称原 CCB 从来不执行它们。

### 本机项目打开

- `POST /api/projects/open` 仅接受本机既有绝对目录，不接受 shell 命令或任意启动参数；与其他 mutation 相同的认证/同源校验。
- 已运行项目直接进入；其他项目复用原 `ccb --safe` 和原启动流程。不会默认绕过权限、force、重启已有 Agent 或因导航启动任务。
- managed worktree 回映原项目；同一真实目录不能因别名重复启动。启动有界、并发明确冲突、未知结果不自动重放；失败保留输入，提供可见诊断。
- registry 更新必须同时覆盖工作台与原 gateway 的 project lookup、任务/会话/终端入口；列表可见不等于闭环可用。
- 关闭对话框不假称取消启动；晚到结果不得抢走后来主动切换的项目/Agent；旧项目列表响应不得移除刚注册的项目。
- 项目启动 unknown 的 canonical-root 防重保护属于当前服务实例内存，不跨后端重启持久化；后端重启后应先核对原 CCB 状态。
- 现有配置页的保存、创建、重启提示保持原语义，界面展示当前绑定而非臆造待生效状态。首版无一键删除/合并。

## 5. 数据、终端与长内容预算

以下是实现目标，不是性能实测结果：

- 一份完整当前会话、一个 composer、全局最多一个交互 xterm/pane WS；不按画布节点放大重内容与连接。
- 原生会话仅在专注且相应来源 tab 可见时 hydration/拉取；jobs 仅实际呈现相应专注/上下文需求时获取。对话并未选中时不为每张卡拉完整日志。
- 轮询请求完成后再安排下一次；同一资源最多一个 in-flight。项目/Agent/epoch 切换中止旧请求，旧结果不能覆盖新选择。
- hidden 不新发后台读取，已有读取 in-flight 可中止；这不取消已提交 Job 或把 mutation 判为失败。visible 后补真实快照，不重放 mutation 或静默重发未知派活。
- 默认显示最近 20 条，提供明确“加载更早”；这是有边界的渐进呈现，**不是消息列表虚拟化已实现**，也不扩展原 CCB 历史保存范围。
- 长内容用标准 `details` 按需展开为纯文本，保留可访问完整原文，不无提示截断；仅 CSS 隐藏已挂载的巨型 Markdown 不算按需 hydration。
- 保留原 xterm 与源 pane 栅格；Resizable 仅改善终端上下拖动高度/键盘 separator，不为浏览器强 resize 原生 pane，也不重做侧栏 frame。
- xterm scrollback 上限不等于没有传输积压；慢消费/积压须有可见诊断，不能靠静默丢输出制造流畅。

组件复用和版本边界见[逐功能矩阵](../research/muxary-expansion-product-review.md#6-逐功能复用矩阵)，不把 UI 原型附带 SDK 带入任务内核。

## 6. 前瞻性能与消融协议

**本节是采集前确定的协议。实际执行、偏差、全部失败与各冻结版本结果见[扩展验收](../research/muxary-expansion-validation.md)，不由协议推导通过，不改写旧样本。**

### 环境、负载和样本

1. 记录机器/CPU/内存、电源模式、显示刷新率、OS、独立无登录 Chrome 版本、生产 build/hash、依赖 lock/hash、fixture/hash、视口、网络条件与浏览器扩展状态。
2. UI Agent 数取 **1 / 20 / 100**；每个分别测普通视口和 fit-all。100 UI 节点不等于启动 100 个 CLI；CLI 实际联通另列，不以 stubs 取代真实联通声明。
3. 同一固定脚本包含定轨迹 pan/zoom、定位首/中/末 Agent、至少 20 次选择、返回专注与中文输入。手势轨迹、速度、顺序、随机 seed 在测前固定。1 节点时明确是同目标 no-op 激活，不算 20 次目标切换；以 fill 写入中文草稿时，不冒称实际 OS 输入法 composition 已验证。
4. 每 cell 固定 2 次热身，热身记录保留但与正式结果分开；随后 **5 次正式 reps，全部保留**。不得挑 80% 样本、重跑到通过或删失败。预先写明排除条件，排除项及理由仍报告。
5. 冷启与稳定交互分开，冷启 longtask 不混入稳定窗口门槛；1440×1000 为桌面性能主样本，390×844 补移动正确性与覆盖情况，不混合两个视口的分布。Headless VM 的 rAF gap 不等于 GPU paint FPS；记录实际 visibility/focus，无法取得物理刷新率、电源模式时明确其不可得。
6. 另设 1MB/10MB 单条内容、每秒 1000 行突发日志、慢网络超过轮询周期、隐藏/恢复 tab、断网重连。若真实入口拒绝大数据，记录其拒绝，并用**单独标注的渲染 fixture**验证下游；不能把早拒绝当作下游机制有效。

### 测量与建议门槛

| 指标 | 定义与预定门槛 | 报告要求 |
| --- | --- | --- |
| frame gap | 固定交互窗口 rAF gap，每 rep p95 ≤ **32ms** | 全 5 reps 的 p50/p95/p99/max；普通/fit-all 分表 |
| 选择响应 | 输入事件至目标 chip/选中态 DOM 正确后的下一 rAF 绘制机会，每 rep p95 ≤ **100ms** | 保存每次选择，不用仅网络返回耗时替代；不是 CWV INP 或物理像素延迟 |
| long task | 交互窗口无 **>200ms** long task | 每 rep 全部 long task；冷启另报，不藏在平均数 |
| 数据/DOM | DOM、HTTP/WS 字节、连接/订阅数与保留数据量 | 逐项报告；DOM 少不是数据完整性的 oracle |
| 持续性 | 重复交互及恢复后不重复任务、不错目标、不丢可访问原文 | 功能门槛，不能用帧率抵消错误 |

每个 cell 的 5 次正式运行均按预定规则报告与判断；某次失败就是该样本失败，不能以“其余 80% 可重复”抹除。测量噪声及设备适用范围必须随结论保留。同机浏览器、测试/构建或观察者自身分析等 CPU/IO 活动逐项记录，不据此排除样本或补跑到通过；5 对 rep 仅作描述比较，不据此作显著性或无限规模保证。源码变化后另建冻结 release 完整执行，不拼接旧版或中止版样本。

### 单因素消融与正确性对照

| 因素 | 只改变什么 | 保持不变 / 可证伪结果 |
| --- | --- | --- |
| 画布视口裁剪 | culling on/off | 固定源码快照、lock、工具链、fixture、1/20/100 模型节点、普通/fit-all、引擎、卡内容、手势和取数；两份生产压缩 build 仅切换该编译因素，不声称同一 binary/hash 或 minifier 只改一字节；若无明确收益，不强留机制 |
| 重内容 hydration | 非可见重内容挂载/按需挂载 | 原文/数据量、网络输入和刷新周期不变；比较 commit、DOM、heap、输入延迟，同时全部原文仍可展开访问 |
| 原生会话按需取数 | 未选来源是否拉取 | 端点、响应数据和周期不变；比较请求/字节/最大并发，不将其收益归因给 DOM culling |
| hidden 暂停 | 应用自身 visibility gate on/off | 同切换脚本/页面/负载；记录浏览器原生后台限速混淆，验证无新发及恢复快照，不借此证明其他机制 |
| 无重叠轮询 | 完成后安排下一次 / 旧固定 interval 基线 | 相同慢 fixture 与周期；验证每资源 in-flight ≤1，失败仍可见，不按收到更少数据宣称渲染优化 |

数据完整性应以模型数据、来源/cursor、全部条目的可导航/可展开性和原文校验检查。fit-all 以全部模型 bounds 是否位于视口内检查，不拿普通视口的裁剪收益冒充全景收益。虚拟化或裁剪本来就不把全部内容挂在 DOM，不能要求“DOM 渲染条数 = fixture 总条数”或以 culling-off 为正确性 oracle 再据此制造通过或失败。没有引入消息虚拟化库时不得宣称其消融已经完成。
