# ADR-0001：Muxary 的产品、运行内核与兼容边界

- 状态：**已接受产品/内核边界；Q7 最终确认，2026-11-11**。
- 日期：2026-11-11。
- 范围：产品入口、CLI 分发、Web 与现有 Agent 控制面。

## 背景

用户希望在 CCB 8.7.22 基础上开发 Muxary，将配置 Web 升级为能日常使用的 Agent 工作台，并支持 CodeBuddy。现有 ccbd 已拥有任务队列和持久化生命周期；移动网关的普通发送回执并不是可靠任务完成。完整移动客户端也不能直接构建为 Web。详见 [事实核查](../research/muxary-existing-surfaces.md) 与 [SPEC](../specs/muxary-workbench.md)。

## 决定

1. 复用现有控制面和任务权威，在浏览器边界做必要适配；不并列创建第二套任务调度/完成状态机。
2. 从 21st 选取可核查来源与许可的 UI 源码，仅承担表现与交互，不为组件示例重写 Agent 运行内核。最终选择 AgentChat Basic 的开源组件子集，React/Vite 客户端与现有 Python 控制面同源，不引入 21st 云运行时；详见 ADR-0002。
3. `muxary` 为新主命令，内部 `CCB_REQ_ID` / `CCB_DONE`、会话字段等仅在确有必要时迁移。`muxary` 默认 Web，`muxary tui` 保留 TUI，`ccb` 保持旧默认行为；独立目录验收后备份并替换本机入口。
4. 首版单机个人优先，桌面式 Web 操作现有 CCB；不新增完整 IDE、团队账号或云托管，不虚构全 Provider 审批。

## 实际比较过的路线

- 仅美化现有配置页：不能满足通过 Web 日常派活、观察、接管与获取结果的目标。
- 直接将现有 Flutter 客户端编译为 Web：当前无 web target 且 transport 依赖 `dart:io`，不是无需适配的捷径。
- 新建独立运行内核或使用组件配套 Agent 云：现有任务能力已存在，将引入第二套状态权威和部署边界；当前没有支持其必要性的证据。
- 保留内核、增加 Web 操作边界并复用 UI：用户已接受路线；许可、原型评审与闭环验证单独留证。

## 后果与未决事项

更新源和 release 身份不能只改 banner；兼容 `ccb` 入口按用户要求在验收后替换，原安装、配置和会话须备份可回滚。审批、会话恢复及冷项目启动等能力必须逐一验证，而非由界面承诺通用支持。依赖和 Provider 覆盖形成独立测试矩阵。已实现工作台与本机 Linux 验证；逐项状态见 [验收记录](../research/muxary-validation.md)。没有将本地实现等同于 npm/GitHub release 或其他平台通过。
